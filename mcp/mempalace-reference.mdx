## Exact topology and ownership

~~~text
ChatGPT or another approved remote MCP client (pending enablement)
    -> Cloudflare MCP Portal: https://mcp-server.datament.sk/mcp
    -> Cloudflare Access Service Auth for mempalace.datament.sk
    -> https://mempalace.datament.sk/servers/mempalace/mcp
    -> Cloudflare Tunnel / Traefik in Dokploy
    -> http://172.18.0.1:18086
    -> mempalace-bridge (hardened Caddy container, Bearer required)
    -> http://127.0.0.1:8006/servers/mempalace/mcp
    -> existing PM2 mcp-proxy -> existing MemPalace MCP
    -> /home/datament/.mempalace/palace

Local-only health:
    http://127.0.0.1:18087/healthz

Existing local consumers:
    Claude Code uses http://127.0.0.1:8006/servers/mempalace/sse
    Other local proxy services coexist on :8006 and must not be exposed
~~~

**Traefik target:** http://172.18.0.1:18086 (no MCP path appended to the target).  
**MCP Portal upstream URL:** https://mempalace.datament.sk/servers/mempalace/mcp (include the path).  
**Existing PM2 listener:** 127.0.0.1:8006 (do not use http://172.18.0.1:8006 as a Traefik target).  
**Container network mode:** host, with Caddy deliberately bound to the gateway and health on localhost.  
**Host user:** datament, UID:GID **1001:1001**.

The public domain name is **mempalace.datament.sk**, not the earlier proposed memory.datament.sk. The host gateway **172.18.0.1** is the docker_gwbridge address on this server. Binding to host 127.0.0.1 is not the same as binding to that gateway.

Keep one authoritative palace. Do not replace the local mcp-proxy, change the existing mining/sync jobs, reinitialize the palace, or expose every service on port 8006.

The observed Dokploy Compose project label is **ai-agents-mempalacebridge-hutugi**. There must be **only one running container** named mempalace-bridge bound to port 18086. The existing raw Compose definition in Dokploy remains the active deployment source unless Dokploy has explicitly been configured to deploy from a file or Git. The deployed image was built locally as **datament/mempalace-caddy:2.10.2-rootless** from **caddy:2.10.2-alpine**, removing the unnecessary Linux file capability from /usr/bin/caddy:

~~~dockerfile
FROM caddy:2.10.2-alpine
RUN setcap -r /usr/bin/caddy \
    && test -z "$(getcap /usr/bin/caddy)"
~~~

A .dockerignore consisting of * and !Dockerfile keeps secrets and logs out of the build context. The original official image could not execute with the chosen least-privilege combination; the custom image succeeded without dropping those restrictions.

The **Bearer token is managed in Dokploy Environment** as MEMPALACE_BRIDGE_TOKEN. A matching private copy was created at secrets/bridge.env (0600). A Compose env_file pointing to that absolute host file caused Dokploy's deployment preparation to fail; replacing it with environment interpolation in Dokploy resolved the deployment issue. The local token and the value in the running container were initially different and later synchronized.

Caddy's verified security design includes: the sole remote MCP path /servers/mempalace/mcp; exact Authorization Bearer matching; removal of the bridge Authorization header before forwarding upstream; request size limit configured at 8 MB; no public health route; private health at 127.0.0.1:18087; JSON access logging with rotation and sensitive-header redaction; no Caddy admin API; no TLS termination at Caddy; an HTTP upstream to the local PM2 proxy. The **source of truth for exact current Caddy directives is the running host Caddyfile**, because its final formatted bytes were not copied into this documentation.

## Authentication: three independent controls

1. **Cloudflare MCP Portal user/client authentication:** ultimately controls which approved ChatGPT or other clients may use the portal. It is separate from upstream service credentials.
2. **Cloudflare Access on mempalace.datament.sk:** a Service Auth policy must explicitly **include the correct MemPalace service token**. Send CF-Access-Client-Id and CF-Access-Client-Secret. A valid Caddy Bearer token without these headers returned HTTP 302 to Cloudflare Access login.
3. **Caddy application Bearer token:** send Authorization: Bearer TOKEN_VALUE. A missing or mismatched Bearer value returns Caddy JSON HTTP 401. Store the token privately in Dokploy and the protected local secrets/bridge.env.

The Access credentials and Caddy Bearer credential are **different secrets**; all three request headers are required for remote upstream calls when both layers are enabled. The successful public POST initialize test returned MCP JSON with HTTP 200 only after the Access policy included the service credentials.

Cloudflare MCP Portal intended upstream values:

| Field | Value |
| --- | --- |
| Server name | mempalace |
| Upstream URL | https://mempalace.datament.sk/servers/mempalace/mcp |
| Transport | Streamable HTTP |
| Upstream credentials | CF-Access-Client-Id, CF-Access-Client-Secret, Authorization: Bearer TOKEN_VALUE |
| Require per-user upstream OAuth | Do not require if the portal uses its configured service credentials; preserve portal-side user/client authentication |
| Enabled for remote clients | **No, until server-side read-only protection and tests pass** |

Some Cloudflare UIs accept a plain Bearer value; others support custom upstream headers or an API credential object. Do not paste a JSON header map into a plain Bearer field. Verify the exact active Cloudflare field/schema and keep all secrets out of screenshots, change logs and this repository.

## Reproducible verification commands

**1. Local private health and route isolation:**

~~~bash
curl --noproxy '*' -sS -o /dev/null \
  -w 'Health: %{http_code}\n' http://127.0.0.1:18087/healthz

curl --noproxy '*' -sS -o /dev/null \
  -w 'Missing Bearer: %{http_code}\n' -X POST \
  http://172.18.0.1:18086/servers/mempalace/mcp

curl --noproxy '*' -sS -o /dev/null \
  -w 'Other MCP: %{http_code}\n' \
  http://172.18.0.1:18086/servers/playwright/mcp
~~~

Expected: 200, 401, 404, respectively. The private health listener does not prove the proxy or memory backend is healthy; use a separate authenticated MCP initialize and harmless recall to check those layers.

**2. Authenticated public MCP initialize:** Prompt for Cloudflare service credentials and read the local Bearer without printing it. Do not paste a token into a repository, shell history or issue.

~~~bash
BASE=/home/datament/project/mempalace/bridge

read -rsp 'Cloudflare Client ID: ' CF_ID; echo
read -rsp 'Cloudflare Client Secret: ' CF_SECRET; echo
BEARER=$(sed -n 's/^MEMPALACE_BRIDGE_TOKEN=//p' "$BASE/secrets/bridge.env")

printf 'header = "CF-Access-Client-Id: %s"\nheader = "CF-Access-Client-Secret: %s"\nheader = "Authorization: Bearer %s"\n' \
  "$CF_ID" "$CF_SECRET" "$BEARER" |
  curl --config - --noproxy '*' --silent --show-error \
    --max-time 20 -w '\nHTTP %{http_code}\n' \
    -H 'Content-Type: application/json' \
    -H 'Accept: application/json, text/event-stream' \
    -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"cloudflare-access-test","version":"1.0"}}}' \
    https://mempalace.datament.sk/servers/mempalace/mcp

unset CF_ID CF_SECRET BEARER
~~~

Expected: HTTP 200 with protocolVersion 2025-03-26 and serverInfo name mempalace (reported MCP server version 1.27.2 on 15 November 2026). Do not print response headers with session cookies or identifiers when sharing test output.

**3. Structured access-log diagnostics:**

~~~bash
BASE=/home/datament/project/mempalace/bridge
ls -lh "$BASE/logs/"
tail -n 20 "$BASE/logs/mempalace-access.log" |
  jq -c '{status, method: .request.method, duration, authorization}'
~~~

The operator observed access log records, including authorization values denied and not_found. Confirm that authorization headers, Access client secrets, session IDs, raw queries and memory contents are absent before enabling long-term retention.

## Completed deployment and troubleshooting timeline

All items below were observed on 15 November 2026 unless marked as explanatory context:

1. **Inventory existing runtime.** /home/datament/.local/bin/mempalace and mempalace-mcp exist; MemPalace CLI is 3.11.0; the palace has 70,889 drawers. Claude Code had a working SSE connection through local mcp-proxy.
2. **Verify MCP proxy.** PM2 mcp-proxy in /home/datament/project/mcp-proxy listens at 127.0.0.1:8006. Local /servers/mempalace/sse returned HTTP 200 and text/event-stream; the short curl timed out because SSE remains open.
3. **Verify Streamable HTTP.** A GET to /servers/mempalace/mcp returned HTTP 400, which did not establish a transport failure. A valid POST initialize returned HTTP 200 and an MCP session ID.
4. **Inventory tools.** A session-based tools/list returned the 47 names documented above, including write and delete operations.
5. **Identify Docker gateway.** 172.18.0.1/16 is docker_gwbridge. The PM2 process does not listen on this address, so Traefik must not target 172.18.0.1:8006.
6. **Create isolated Caddy bridge in Dokploy.** A host-networked bridge listens on 172.18.0.1:18086 and forwards only /servers/mempalace/mcp to 127.0.0.1:8006. A test initialize through the gateway returned HTTP 200. Playwright and WordPress tests returned 404.
7. **Consolidate under the datament-owned MemPalace project.** The files moved to /home/datament/project/mempalace/bridge. The host account is already datament; sudo -iu datament was not needed and was not permitted by sudo policy.
8. **Create Bearer token.** A random 32-byte token was created as MEMPALACE_BRIDGE_TOKEN in private secrets/bridge.env with file mode 0600. The original compose env_file reference failed inside Dokploy deployment preparation, so Dokploy Environment and Compose interpolation were used instead.
9. **Validate Caddy configuration.** The correct one-off command runs caddy validate rather than attempting to execute validate as the image entrypoint. Validation passed; formatting warnings were non-fatal.
10. **Repair hardened container execution.** With user 1001:1001, cap_drop ALL and no-new-privileges, the stock Caddy binary exited with operation not permitted. A locally built custom image removed the unnecessary cap_net_bind_service file capability. The hardened container started normally.
11. **Repair credentials.** Local and Dokploy Bearer values initially failed the equality check; authenticated requests returned 401. After synchronizing them, local authenticated initialization returned HTTP 200.
12. **Separate health endpoint.** The initial /healthz rule on port 18086 had an IP-matcher mismatch and returned 404; a localhost-only listener on 127.0.0.1:18087 returned HTTP 200. Docker reported running and healthy.
13. **Verify public hostname.** Domain corrected to mempalace.datament.sk. A browser without Caddy credentials received the Caddy JSON 401, demonstrating that the public route reached Caddy for that request.
14. **Repair Cloudflare Access Service Auth.** Public POST with Bearer but without accepted Access credentials returned HTTP 302 to Cloudflare login. The MemPalace service credential was missing from the Access application's policy. After inclusion, a public three-header initialize returned HTTP 200.
15. **Do not assume portal readiness.** The successful direct HTTP handshake does not prove that the MCP Portal has synchronized tools, that ChatGPT can call them, or that write operations are refused.

No PM2 restart, palace migration, memory reindexing or modifications to Graphify, Ghost or Logiscool were required for the bridge.

## Rollback and change control

1. First disable **only the MemPalace mapping** in the Cloudflare MCP Portal, if enabled; do not remove other upstreams.
2. If the remote read-only listener or gateway fails, revert only its Caddy upstream to the last tested version, using the backed-up Caddyfile and deployment revision. Restore or rebuild the pinned local Docker image if needed.
3. If the bridge itself fails, stop or redeploy only the Dokploy project ai-agents-mempalacebridge-hutugi after checking its owner and backups. Preserve the host PM2 mcp-proxy and the existing local Claude/Codex connections.
4. Re-run local MCP initialization, 401/404 isolation checks, private /healthz, and public authorized initialize.
5. Never delete, reinitialize, overwrite or migrate the palace as a rollback shortcut. Do not alter independent Graphify, Ghost, Logiscool or mining refresh jobs to troubleshoot this bridge.

Keep the previously working /opt/mempalace-bridge/Caddyfile backup until the replacement and rollback are tested. Keep secret values out of documentation, Docker build context and public repositories.
