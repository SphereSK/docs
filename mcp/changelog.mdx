## 15 November 2026

### Ghost fork deployed and verified

The user deployed the tested Ghost MCP fork through two revisions:
[0539b54](https://github.com/SphereSK/ghst/commit/0539b544cfa1e5cb0537c16f57b4501fdb0aef14)
and [faedd43](https://github.com/SphereSK/ghst/commit/faedd43bf35928ec881393de215c695be4bf51c2).
The final build exposes 37 tools. Its 291 offline tests passed, and deployed bundle
identity, authentication, compact reads, pagination and all three saved snippets
were checked read-only. Live write behavior was not tested in this implementation session.

See the [complete change record](/mcp/changes/2026-11-15-ghost-mcp) and updated
[Ghost reference](/mcp/ghost-reference). This deployment supersedes the earlier
image-upload proposal below; it does not erase the earlier observations.

### Shared documentation workflow prepared

Added [agent change tracking](/mcp/agent-change-tracking), shared repository rules,
a documentation PR template and a proposed validation workflow. The selected
policy is documentation PRs for review. Cross-repository Autopilot activation and
installation of rules in other agent clients remain pending. MemPalace integration
was not implemented in this session.


### Ghost reference added

A new page, [Ghost reference](/mcp/ghost-reference), records the Ghost MCP tools exposed through the portal, the SEO and social fields, HTML card handling and the image upload limit.

Observed in a client session on this date:

- `ghost_post_update` saved `meta_title`, `meta_description`, `og_title` and `og_description` on a published post and returned the saved values.
- A post body sent as `html` was converted to editor blocks. Markup wrapped in HTML card markers was kept unchanged.
- `ghost_image_upload` failed with `ENOENT` for a file path from the client's workspace, because the server resolves `file_path` on its own file system. A change to accept base64 content or a URL is proposed and not implemented.
