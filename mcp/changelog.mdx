## 15 November 2026

### MemPalace MCP baseline documented; remote integration not yet verified

Added [MemPalace reference](/mcp/mempalace-reference) covering the reported local installation, upstream architecture and tools, authentication boundaries, storage and refresh ownership, backup requirements, deployment checks, monitoring, troubleshooting and rollback.

Evidence collected in this documentation session:

- The Datament MCP Portal listed Ghost, Graphify and Logiscool, but **not MemPalace**. No live MemPalace portal tool discovery or end-to-end client call was verified.
- The previous operator handoff described an existing local palace, an MCP proxy and refresh jobs, but the installed version, runtime flags, writer ownership and backup restore status were not independently checked.
- The upstream MemPalace source documents HTTP MCP serving, bearer authentication, read-only mode and health endpoints. These upstream capabilities are not a verified Datament deployment configuration.
- No deployment, portal route, local memory, job schedule, credentials or production service was modified. Remote read-only integration and restore validation remain planned.

Reuse [Connection setup](/mcp/connection-setup) for the common Cloudflare and ChatGPT steps. The reference explicitly records missing acceptance evidence rather than treating a local installation as a completed remote deployment.

### Ghost reference added

A new page, [Ghost reference](/mcp/ghost-reference), records the Ghost MCP tools exposed through the portal, the SEO and social fields, HTML card handling and the image upload limit.

Observed in a client session on this date:

- `ghost_post_update` saved `meta_title`, `meta_description`, `og_title` and `og_description` on a published post and returned the saved values.
- A post body sent as `html` was converted to editor blocks. Markup wrapped in HTML card markers was kept unchanged.
- `ghost_image_upload` failed with `ENOENT` for a file path from the client's workspace, because the server resolves `file_path` on its own file system. A change to accept base64 content or a URL is proposed and not implemented.
