Change ID: `2026-11-15-ghost-mcp`. All human-facing times use Europe/Bratislava. Status: **implemented, tested, deployed and read-only verified**.

## Problems resolved

- `ghost_site_list` returned an empty alias array even though environment-backed credentials worked. It now also reports a sanitized connection descriptor, without inventing a selectable alias.
- The list `status` argument was sent as a query parameter that Ghost ignored. It now composes with Ghost's filter expression.
- Full list responses included content and expanded author data. Optional `fields` and `formats` support smaller reads without changing defaults.
- Excerpt and code-injection fields were not mapped, so an apparently accepted argument could be discarded. They now have explicit schemas and payload mappings.
- `slug` selected an existing resource; it did not rename it. `new_slug` now expresses a rename separately.
- Image upload expected a path on the MCP server. `image_url` now downloads supported public HTTPS images and uploads the bytes.
- Saved snippets returned empty Mobiledoc placeholders by default. Explicit Lexical reads retrieve the real card data.

See [Ghost reference](/mcp/ghost-reference) for the current tool contract and limitations.

## Limits of verification

No live create, update, rename, upload, publish, email or snippet-insertion calls were made during this work. Live write persistence was not tested; it is covered by offline tests of the exact deployed code. A future live draft test still requires explicit authorization.

The current chat continued to expose older connector definitions despite the server advertising the new schemas. Server deployment and client/Portal discovery are separate checks; do not declare client refresh complete from a direct server check alone.

Earlier rendered-HTML reads confirmed that `/kontakt/` had no description meta tag and used excerpt fallback for social previews. A sampled published article rendered its SEO and social metadata. These were audits, not content corrections.
