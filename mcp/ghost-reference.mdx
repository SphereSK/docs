The Ghost MCP server lets an AI client read and edit posts on a Ghost site through the Datament MCP portal. This page records what the server was observed to do from a connected client on 15 November 2026 (Europe/Bratislava), including one limit that blocks image uploads from remote clients.

These are dated observations from client sessions, not a description of the server's source code. For the generic steps to connect a server, see [Connection setup](/mcp/connection-setup). For dated records, see the [Changelog](/mcp/changelog).

## Tools exposed through the portal

The portal exposes the Ghost tools with the prefix `ghost-mcp_`. The following tool names were listed by the client.

| Area | Tools |
| --- | --- |
| Posts | `ghost_post_list`, `ghost_post_get`, `ghost_post_create`, `ghost_post_update`, `ghost_post_publish`, `ghost_post_schedule`, `ghost_post_delete` |
| Pages | `ghost_page_list`, `ghost_page_get`, `ghost_page_create`, `ghost_page_update`, `ghost_page_delete` |
| Tags | `ghost_tag_list`, `ghost_tag_get`, `ghost_tag_create`, `ghost_tag_update`, `ghost_tag_delete` |
| Media and themes | `ghost_image_upload`, `ghost_theme_upload` |
| Site | `ghost_site_info`, `ghost_site_list`, `ghost_webhook_create` |
| Analytics | `ghost_stats_overview`, `ghost_stats_web`, `ghost_stats_web_table`, `ghost_stats_growth`, `ghost_stats_posts`, `ghost_stats_post`, `ghost_stats_post_web`, `ghost_stats_post_growth`, `ghost_stats_post_referrers`, `ghost_stats_post_newsletter`, `ghost_stats_email`, `ghost_stats_email_clicks`, `ghost_stats_email_subscribers` |

Most tools accept an optional `site` parameter that selects a configured site alias. `ghost_site_list` lists the aliases without credentials.

## SEO and social fields

`ghost_post_update` and `ghost_post_create` accept these fields, and the update call returns the saved values in its response:

- `meta_title` and `meta_description`
- `og_title`, `og_description` and `og_image`
- `twitter_title`, `twitter_description` and `twitter_image`
- `canonical_url`
- `feature_image`, `feature_image_alt` and `feature_image_caption`

`feature_image`, `og_image` and `twitter_image` take a URL. They do not take a file.

An update applies to a published post immediately. Read the response to confirm the saved values before you report the change as done.

## Updating post content with HTML

`ghost_post_update` accepts the post body in the `html` field. Ghost converts it to its own editor format, so plain paragraphs, headings, lists and images become normal editor blocks.

To keep custom markup unchanged, wrap it in HTML card markers:

```html
<!--kg-card-begin: html-->
<aside class="lsc-cta lsc-cta--demo">...</aside>
<!--kg-card-end: html-->
```

Content between the markers was stored as an HTML card with its classes and inline `style` attributes intact. Use this for call-to-action snippets and for blocks that need tighter spacing than the theme gives to headings.

<Warning>
  Sending `html` replaces the whole post body. Read the post first with `ghost_post_get` and `formats: "html"`, then send the complete new body, including every existing HTML card.
</Warning>

## Image upload limit

`ghost_image_upload` takes a required `file_path` and the optional parameters `purpose`, `ref` and `site`.

The server resolves `file_path` on its own file system. A client that runs elsewhere, such as a cloud AI session, cannot place a file there. An upload with a path from the client's workspace failed with this error:

```text
ENOENT: no such file or directory, open '/home/claude/header/ukazkova-hodina-logiscool-trnava.jpg'
```

As a result, a remote client cannot upload a new image or set a new header image by itself.

### Workarounds

- **Upload in Ghost Admin.** Open the post, select **Add feature image** and choose the file. The client can then set `feature_image_alt` and `og_image` through `ghost_post_update`.
- **Use a public URL.** If the image is already reachable at a public URL, set `feature_image` to that URL with `ghost_post_update`.

### Proposed change

<Note>
  This change is a proposal. It is not implemented.
</Note>

Extend `ghost_image_upload` so that it accepts the image without a server-side path, for example as base64 content or as a URL that the server fetches. A remote client could then upload an image and set it as `feature_image` in the same session.

## Deleting content

In an earlier client session, deleting a test draft was refused because the server runs without `--enable-destructive-actions`. This was not tested again on 15 November 2026. Delete drafts in Ghost Admin until the flag is enabled.
