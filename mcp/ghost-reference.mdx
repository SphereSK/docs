The Ghost MCP server lets authorized clients work with Ghost content through the Datament portal. The deployed fork at commit [faedd43](https://github.com/SphereSK/ghst/commit/faedd43bf35928ec881393de215c695be4bf51c2) exposes **37 tools** for the configured `posts,pages,tags,site,stats` groups. This page was updated after read-only server verification on 15 November 2026 (Europe/Bratislava).

The matching build passed 291 offline tests. New write paths were tested with mocks, not live content. Do not publish, email, change posts/pages or run live draft tests without explicit user authorization. See the [deployment record](/mcp/changes/2026-11-15-ghost-mcp) for evidence and limits, and [Connection setup](/mcp/connection-setup) for the generic connection workflow.

## Tools exposed through the portal

The portal exposes the Ghost tools with the prefix `ghost-mcp_`. Client definitions can lag behind deployment; the following tools were verified directly against the running server.

| Area | Tools |
| --- | --- |
| Posts | `ghost_post_list`, `ghost_post_get`, `ghost_post_create`, `ghost_post_update`, `ghost_post_publish`, `ghost_post_schedule`, `ghost_post_delete` |
| Pages | `ghost_page_list`, `ghost_page_get`, `ghost_page_create`, `ghost_page_update`, `ghost_page_delete` |
| Tags | `ghost_tag_list`, `ghost_tag_get`, `ghost_tag_create`, `ghost_tag_update`, `ghost_tag_delete` |
| Media and themes | `ghost_image_upload`, `ghost_theme_upload` |
| Site | `ghost_site_info`, `ghost_site_list`, `ghost_webhook_create` |
| Saved snippets | `ghost_snippet_list`, `ghost_snippet_get` |
| Analytics | `ghost_stats_overview`, `ghost_stats_web`, `ghost_stats_web_table`, `ghost_stats_growth`, `ghost_stats_posts`, `ghost_stats_post`, `ghost_stats_post_web`, `ghost_stats_post_growth`, `ghost_stats_post_referrers`, `ghost_stats_post_newsletter`, `ghost_stats_email`, `ghost_stats_email_clicks`, `ghost_stats_email_subscribers` |

Most tools accept an optional `site` parameter that selects a configured site alias. `ghost_site_list` lists saved aliases without credentials and adds a sanitized `connection` descriptor for direct/environment credentials. An empty `sites` array can coexist with a working connection; omit `site` when no selectable alias exists.

## Metadata and slug updates

Post and page create/update tools expose these nine SEO fields:

- `meta_title`, `meta_description`
- `og_title`, `og_description`, `og_image`
- `twitter_title`, `twitter_description`, `twitter_image`
- `canonical_url`

They also accept `custom_excerpt` (up to 300 characters) and `codeinjection_head` / `codeinjection_foot` (up to 65,535 characters each). SEO title limits are 300 characters, descriptions 500, and HTTP(S) URL fields 2,000. These are input limits, not recommended search-result lengths.

Omit a field to preserve it; send `null` to clear its override. A metadata-only request sends the selected fields and the current `updated_at` collision timestamp, not the content, status, slug or unrelated metadata. SEO/injection post updates return conflicts rather than automatically retrying over a newer edit.

`slug` remains the existing lookup slug on updates. Set `new_slug` to rename explicitly. Post creation now accepts `slug`, as page creation already did. A rename changes the public URL; this tool does not configure redirects.

Post tools also retain `feature_image`, `feature_image_alt` and `feature_image_caption`. Image fields take URLs. An explicitly supplied code-injection value replaces that whole field; preserve any existing code you intend to keep. For JSON-LD, include the script element and inspect existing theme-generated structured data to avoid duplicates.

## Compact reads and pagination

Post/page list and get tools accept `fields` and `formats` (`html`, `lexical` or `html,lexical`). Defaults and response envelopes remain compatible. List limits remain numeric, up to 100; follow `meta.pagination.next` instead of assuming one page is complete.

```json
{
  "limit": 10,
  "page": 1,
  "status": "published",
  "fields": "id,slug,status,updated_at,meta_title,meta_description"
}
```

The list `status` argument now composes with the Ghost filter expression. Direct production tests returned only requested fields and distinct results for pages 1 and 2. Verify rendered public HTML separately: a null API override may produce a theme fallback rather than a missing meta tag.

## Updating post content with HTML

`ghost_post_update` accepts the post body in the `html` field. Ghost converts it to its own editor format, so plain paragraphs, headings, lists and images become normal editor blocks.

To keep custom markup unchanged, wrap it in HTML card markers:

```html
<!--kg-card-begin: html-->
<aside class="lsc-cta lsc-cta--demo">...</aside>
<!--kg-card-end: html-->
```

Content between the markers was stored as an HTML card with its classes and inline `style` attributes intact. Use this for call-to-action snippets and for blocks that need tighter spacing than the theme gives to headings.

<Warning>
  Sending `html` replaces the whole post body. Read the post first with `ghost_post_get` and `formats: "html"`, then send the complete new body, including every existing HTML card.
</Warning>

## Upload images from a path or URL

`ghost_image_upload` accepts exactly one source:

- `file_path`: a readable path on the **MCP server**, not a path on your remote client.
- `image_url`: a direct public HTTPS URL. The server downloads bytes and uploads them to Ghost as multipart data.

Optional `purpose`, `ref` and `site` remain available. URL downloads allow PNG, JPEG, GIF and WebP, with a 10 MiB limit and a 15-second request deadline. The implementation rejects redirects, embedded credentials, nonstandard ports, private/reserved destinations and IPv6-only hosts, and pins validated public IPv4 DNS results. Ghost credentials are never sent to the source image host.

For a redirecting URL, use the final direct image URL. Unsupported formats need a separate conversion or local-file workflow. Uploading does not automatically insert the image into a post. Schema and upload payload behavior passed offline tests; no live upload was performed in the deployment check.

## Reuse saved editor snippets

`ghost_snippet_list` returns paginated names and IDs without large content. `ghost_snippet_get` returns a saved snippet in its native format, defaulting to `formats: "lexical"`. Use `"mobiledoc"` explicitly for legacy content. HTML is not a supported snippet format on the verified Ghost deployment.

The three saved CTA snippets were retrieved successfully. Each contains a clipboard-shaped Lexical object with `namespace` and `nodes`. Their default Mobiledoc responses were empty placeholders, not evidence of missing content.

Post/page create/update accepts a JSON-string `lexical` document as an alternative to `html`. To compose a new document from a snippet, inspect its format and preserve the saved nodes inside a Lexical root, as shown in the [source README](https://github.com/SphereSK/ghst/blob/faedd43bf35928ec881393de215c695be4bf51c2/README.md). Do not send both content formats.

<Warning>
  A `lexical` update replaces the body just as `html` does. Retrieve and preserve the existing document when composing an authorized insertion. Snippet read tools do not insert content or create, edit or delete saved snippets.
</Warning>

## Server discovery versus client discovery

The deployed server passed a direct MCP `tools/list` check for 37 tools and every new input field. The existing chat still exposed older connector definitions. Check the Portal/client tool schemas independently; reconnecting a client is not proof that its definitions refreshed.

## Deleting content

In an earlier client session, deleting a test draft was refused because the server runs without `--enable-destructive-actions`. This was not tested again on 15 November 2026. Delete drafts in Ghost Admin until the flag is enabled.
